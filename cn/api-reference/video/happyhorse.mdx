HappyHorse 是原生音视频同步的视频模型线。本页覆盖两个模型：`happyhorse-1.0` 支持 `generate` 与 `edit` 两个动作，能从文本、首帧图、参考图生成视频，也能改写一段源视频；`happyhorse-1.1` 只做 `generate`，是同一套输入下的参考图档。两个模型共用 `POST /v1/tasks`，参数集合几乎相同，差别在动作、视频输入与音频处理上。

## 快速开始

<CodeGroup>

```bash 文生视频
curl -X POST https://www.qingbo.dev/v1/tasks \
  -H "Authorization: Bearer $WAVE_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: hh-t2v-001" \
  -d '{
    "model": "happyhorse-1.1",
    "action": "generate",
    "prompt": "一只柴犬穿宇航服在月球上行走，电影感光影",
    "resolution": "1080p",
    "aspect_ratio": "16:9",
    "duration": 5
  }'
```

```bash 图生视频（首帧）
curl -X POST https://www.qingbo.dev/v1/tasks \
  -H "Authorization: Bearer $WAVE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "happyhorse-1.1",
    "action": "generate",
    "prompt": "人物缓缓走向镜头",
    "first_frame_image": "https://cdn.example.com/portrait.jpg",
    "resolution": "1080p",
    "duration": 8
  }'
```

```bash 参考图生视频
curl -X POST https://www.qingbo.dev/v1/tasks \
  -H "Authorization: Bearer $WAVE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "happyhorse-1.0",
    "action": "generate",
    "prompt": "保持角色形象，在森林中奔跑",
    "image_urls": [
      "https://cdn.example.com/char-1.jpg",
      "https://cdn.example.com/char-2.jpg"
    ],
    "resolution": "1080p",
    "duration": 6
  }'
```

```bash 视频编辑
curl -X POST https://www.qingbo.dev/v1/tasks \
  -H "Authorization: Bearer $WAVE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "happyhorse-1.0",
    "action": "edit",
    "prompt": "把场景改成雪天，保留人物动作",
    "video_urls": ["https://cdn.example.com/source.mp4"],
    "image_urls": ["https://cdn.example.com/style.jpg"],
    "audio_setting": "origin",
    "resolution": "1080p",
    "duration": 0
  }'
```

</CodeGroup>

提交成功后返回 `task_id`。用 [`GET /v1/tasks/{task_id}`](/cn/api-reference/task/status) 查询结果，也可以用 [`Prefer: wait`](/cn/api-reference/task/submit#请求内等待prefer-wait) 在一次调用里等待，或配置 Webhook。

## 请求参数

<ParamField body="model" type="string" required>
  二选一：`happyhorse-1.0` 或 `happyhorse-1.1`。
</ParamField>

<ParamField body="action" type="string" default="generate">
  - `generate`：生成视频。两个模型都支持
  - `edit`：改写一段源视频，必须提供 `video_urls`。只有 `happyhorse-1.0` 支持
</ParamField>

<ParamField body="prompt" type="string">
  视频内容描述或编辑指令。传了首帧图或参考图时可选，但用于指导运镜与动作。
</ParamField>

<ParamField body="image_urls" type="string[]">
  参考图片 URL 数组，作为主体 / 风格参考生成新画面。`happyhorse-1.0` 在 `edit` 下可以和 `video_urls` 一起传，作为风格参考。
</ParamField>

<ParamField body="first_frame_image" type="string">
  首帧图片 URL。传了之后画幅跟随图片，`aspect_ratio` 不生效。
</ParamField>

<ParamField body="video_urls" type="string[]">
  源视频 URL 数组。只有 `happyhorse-1.0` 的 `edit` 动作接受，必传且只能一段，长度 6–15 秒。
</ParamField>

<ParamField body="resolution" type="string">
  输出分辨率：`720p` 或 `1080p`。
</ParamField>

<ParamField body="duration" type="integer">
  输出时长（秒），`3`–`15` 任意整数。

  `happyhorse-1.0` 的 `edit` 动作输出时长沿用源视频：传 `0` 就是「沿用源视频时长」，传别的值也不改变输出长度。
</ParamField>

<ParamField body="aspect_ratio" type="string">
  画面比例：`16:9`、`9:16`、`1:1`、`4:3`、`3:4`。传了首帧图或源视频时，画幅跟随输入素材。
</ParamField>

<ParamField body="seed" type="integer">
  随机种子。相同请求配相同种子会生成相似结果。
</ParamField>

<ParamField body="audio_setting" type="string">
  音频处理，只在 `happyhorse-1.0` 的 `edit` 动作下生效：`auto` 自动生成音频，`origin` 保留原音轨。
</ParamField>

<ParamField body="watermark" type="boolean" default="false">
  是否给输出视频加水印。两个模型都接受。
</ParamField>

通用的 `callback_url`、`callback_events`、`Prefer: wait`、`Idempotency-Key` 和费用上限请求头见[提交任务](/cn/api-reference/task/submit)。

两个模型都不接受 `n`、`quality`、`generate_audio` 与 `audio_urls`。以上之外的参数会返回 `400`，不计费。

## 限制

| 模型 ID | 条件 | 限制 |
|---|---|---|
| 两个模型 | 每次任务 | 一次任务只产出一个结果，不支持用 `n` 批量生成 |
| `happyhorse-1.0` | `action: "edit"` | 视频编辑需要一条 6–15 秒的源视频；输出时长沿用源视频，`duration` 不生效 |
| `happyhorse-1.0` | `action: "generate"` | `generate` 不接受源视频；改视频请用 `edit` |
| `happyhorse-1.1` | 视频输入 | 不接受 `video_urls`，没有 `edit` 动作 |

## 计费

两个模型都按**分辨率档 × 秒数**计费。`price_config.video_prices` 按分辨率分键，`happyhorse-1.0` 的价表另按动作分键（`edit_720p` / `edit_1080p`），编辑与生成各走各的档。

| 模型 ID | 计费维度 | 计费秒数 |
|---|---|---|
| `happyhorse-1.0`（`generate`） | 分辨率档 × 秒数 | 请求的 `duration` |
| `happyhorse-1.0`（`edit`） | 动作 × 分辨率档 × 秒数 | 源视频时长（6–15 秒） |
| `happyhorse-1.1` | 分辨率档 × 秒数 | 请求的 `duration` |

`edit` 的输出时长沿用源视频，所以计费秒数取源视频的时长，`duration` 不参与。源视频秒数怎么读取、读不出来会怎样，见[视频生成概述](/cn/api-reference/video/overview#输入视频的时长与计费)。

只有成功出片才计费。任务失败、取消，或没有返回可用视频时，全额退款。最终费用以任务响应里的 `cost` 为准——整数 quota，**500,000 quota = 1 USD**，不是美元。

<Note>
**本页不列具体单价**。单价随上游调整，本节只讲计费维度与口径。

实时单价见 `GET /v1/models` 返回的 `price_config`，或控制台「模型市场」。
单次调用的实际费用见任务响应里的 `cost`（整数 quota，500,000 quota = 1 USD）。
</Note>

  "task_id": "task-wave1775285160b950328499",
  "model": "happyhorse-1.1",
  "action": "generate",
  "status": "completed",
  "progress": "100%",
  "created_at": 1775285160,

  "cost": 483750,
  "result": {
    "videos": [
      {
        "expires_at": 1775544360,
        "url": ["https://cdn.example.com/result.mp4"]
      }
    ]
  },

    "cancel": "https://www.qingbo.dev/v1/tasks/task-wave1775285160b950328499/cancel"

`result.videos` 返回生成的视频，`url` 是数组，`expires_at` 是视频链接的过期时间戳。完整字段说明见[查询任务状态](/cn/api-reference/task/status)。

## 可用模型

| 模型 ID | 动作 | 分辨率 | 时长（秒） | 可传的媒体输入 |
|---|---|---|---|---|
| `happyhorse-1.0` | `generate` `edit` | `720p` `1080p` | `3`–`15`；`edit` 沿用源视频时长 | `image_urls` · `first_frame_image` · `video_urls`（仅 `edit`，1 段 6–15 秒） |
| `happyhorse-1.1` | `generate` | `720p` `1080p` | `3`–`15` | `image_urls` · `first_frame_image` |

两个模型都支持 `16:9`、`9:16`、`1:1`、`4:3`、`3:4` 五种画幅。`happyhorse-1.0` 输出原生同步音频；`happyhorse-1.1` 面向参考图生成。
