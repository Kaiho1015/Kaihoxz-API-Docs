title: "通用对话接口"
api: "POST http://localhost:40081/v1/chat/completions"
---

通过 `model` 选择公开模型，同一接口支持非流式、流式和函数调用，不需要知道上游渠道或 Profile。参数是否可用以模型组的已验证能力为准，不承诺所有 OpenAI 参数在每条渠道都支持。

当前联调使用 `http://localhost:40081`；部署后替换为你的网关地址。使用 WaveAPI Key 作为 Bearer 凭据，不能使用生态登录 token 代替模型 Key。

## 已校验的模型指南

- [GPT-5.6 Luna / Terra / Sol](/cn/api-reference/text/gpt-5-6)
- [GPT-5.4 / GPT-5.5](/cn/api-reference/text/gpt-5-4-and-5-5)
- [Gemini 3.6 Flash](/cn/api-reference/text/gemini-3-6-flash)
- [Claude Sonnet 5 / Opus 5](/cn/api-reference/text/claude-5)
- [Claude Fable 5.1](/cn/api-reference/text/claude-fable-5-1)
- [Grok 4.6](/cn/api-reference/text/grok-4-6)

可用性以当前模型目录和 Key 权限为准。旧目录中的模型不自动代表已上架；2024 年 9 月以前发布或已经退役的模型不在新目录中开放。

## 最小调用

```bash
curl http://localhost:40081/v1/chat/completions \
  -H "Authorization: Bearer $WAVE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"gpt-5.6-luna","messages":[{"role":"user","content":"Reply with the single word OK."}],"reasoning_effort":"none","max_completion_tokens":128,"stream":false}'
```

`model` 和 `messages` 必填。GPT 示例使用已验证的 `reasoning_effort: "none"` 和 `max_completion_tokens`；Claude 示例使用 `max_tokens`。这些参数不能不加区分地复制到所有模型。`temperature`、推理档位和多模态输入同样按模型指南选择。

## 流式

在同一请求添加 `stream: true` 和 `stream_options: {"include_usage": true}`。响应为 SSE：累加 `choices[].delta.content`，独立读取最终 `usage` 帧，再处理 `[DONE]`。最终用量帧可以没有 choices；不能因为内容已结束就忽略它。连接中断不等于调用免费，先查看已有账单再决定是否重发。

## 结构化输出

以下请求已在 GPT-5.6 Luna 路由验证。只有明确支持此能力的模型才能使用；当前 Claude 路由会在预扣前拒绝 JSON Schema / JSON 模式。

```json
{
  "model": "gpt-5.6-luna",
  "messages": [{"role": "user", "content": "Return an object whose answer is OK."}],
  "reasoning_effort": "none",
  "max_completion_tokens": 128,
  "response_format": {
    "type": "json_schema",
    "json_schema": {
      "name": "answer",
      "strict": true,
      "schema": {"type": "object", "properties": {"answer": {"type": "string", "enum": ["OK"]}}, "required": ["answer"], "additionalProperties": false}
    }
  }
}
```

## 函数调用

函数声明与普通文本共用同一个 URL。返回 `tool_calls` 的函数名与 JSON 参数由你的应用检查并执行；生成工具参数不代表工具已执行。多轮工具流程需按模型支持情况另行验证。

```json
{
  "model": "gpt-5.6-luna",
  "messages": [{"role": "user", "content": "Call record_result with answer OK."}],
  "reasoning_effort": "none",
  "max_completion_tokens": 128,
  "tools": [{"type": "function", "function": {"name": "record_result", "description": "Return a result to the caller.", "parameters": {"type": "object", "properties": {"answer": {"type": "string"}}, "required": ["answer"], "additionalProperties": false}}}],
  "tool_choice": {"type": "function", "function": {"name": "record_result"}}
}
```

## 用量与费用

`prompt_tokens` 包含普通输入及缓存部分；缓存命中和写入是其中的不同计费部分，不能在总输入之外再加一次。`completion_tokens` 包含思考 token，不能重复计费。`usage.cost` 是整数 quota，不是美元；当前换算为 500,000 quota = 1 USD。最终费用以本人文本账本为准，`pricing_pending` 表示仍需核对，不能显示为零费用。

## 当前不开放的参数

内置联网、托管搜索/执行工具和非标准 `service_tier` 尚未配置完整费用，因此在预扣前拒绝。客户端函数调用不属于这些托管工具。Gemini 显式缓存存储同样未开放。原生协议分别见 [Gemini](/cn/api-reference/text/gemini-native)和 [Claude Messages](/cn/api-reference/text/claude-messages)，无需为每个渠道增加一套 URL。
