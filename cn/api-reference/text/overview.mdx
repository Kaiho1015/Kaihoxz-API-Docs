WaveAPI 的文本模型统一走 OpenAI 兼容的 Chat Completions 接口：换模型只改 `model`，不需要按厂商换 URL、换 Key 或了解上游渠道。本页是文本类的目录页——先看调用入口，再看计费口径，最后按厂商查模型 ID、价格和已验证的能力。

新接入一律用 Chat Completions；原生入口只是给已有客户端省迁移成本，不提供更多能力。所有入口都用 WaveAPI Key 作为凭据（Chat / Responses 走 `Authorization: Bearer`，Messages 走 `x-api-key`，Gemini 原生走 `x-goog-api-key`），生态登录 token 不能代替模型 Key，见[认证](/cn/docs/authentication)。

## 计费口径

下面这几条对本页所有文本模型一致；型号差异写在各厂商表的说明列和表下段落里。

- **单位与来源**：价格单位 USD / 100 万 token，2026-09-05 核对。售价按官方标准价九折或原价制定，不高于官方；不使用 Batch、Flex、Priority 等特殊价。
- **输入总量含缓存**：`prompt_tokens` 是输入总量，其中实际报告的缓存命中 / 缓存写入 token 按对应缓存价计费，其余按普通输入价；缓存部分是输入的组成部分，不在总量之外再加一次。
- **思考含在输出里**：`completion_tokens` 已包含 `completion_tokens_details.reasoning_tokens`，思考 token 按输出价计费一次，不再叠加。
- **两项计价型号**：表中缓存读为 `—` 的型号只有输入 / 输出两项价格，响应里的缓存统计也按普通输入价计；显式 `cache_control` 会在预扣前拒绝。
- **长上下文分档**：价格带斜线的型号，以**输入总量**（含缓存）判断档位，达到阈值后整单（输入、缓存、输出）切换到斜线后的价格，不是只对超出部分加价。阈值与「恰好等于阈值」的归属见各厂商段落。
- **时段价**：DeepSeek V4 按请求开始时刻的 UTC 时段定价，见 DeepSeek 段落。
- **额度换算**：分项费用合计后换算成整数 quota，**500,000 quota = 1 USD**；有正用量但不足 1 quota 的请求按 1 quota 计，再应用账户分组倍率并取整。响应里的 `usage.cost` 就是这个整数 quota，**不是美元**。

```text
普通输入 token = prompt_tokens - cached_tokens - cache_write_tokens
费用（USD） = ( 普通输入 token × 输入价
             + cached_tokens × 缓存读价
             + cache_write_tokens × 缓存写价
             + completion_tokens × 输出价 ) / 1,000,000
quota      = 费用（USD） × 500,000，向下取整，最低 1
```

最终扣款以本人账单的文本账务记录为准，状态含义如下：

| 账务状态 | 含义 |
|---|---|
| `reserved` | 已预扣，结果尚未确认；预扣不是最终费用 |
| `pricing_pending` | 已收到用量，但价格或计量信息需要核对；保留预扣，不发布确定费用 |
| `settlement_pending` / `refund_pending` | 等待结算或退款完成 |
| `settled` / `refunded` | 扣费或退款已完成；以最终账务金额核对 |

<Warning>
没有收到完整 `usage`、连接中断或响应缺少费用字段，都**不代表本次调用免费**。先到控制台核对已有用量记录，不要自动重发。
</Warning>

## 缓存

缓存能力按型号分四档，判据是模型组 `price_config` 里配了哪几项缓存价，**不由官方是否支持推断**。
缓存读写按各自单价**替代**对应的普通输入费用，不在输入之外另加一笔。

| 档 | 判据 | 型号 |
|---|---|---|
| 无缓存优惠 | `cache_billing: "input_output"` | 目录中其余全部型号；响应里若带缓存统计，一律按普通输入价计 |
| 只有缓存读 | 配了 `cache_read` | `gpt-5.5` `gpt-5.4` `grok-4.6` `gemini-3.6-flash` `gemini-3.7-flash` `gemini-3.8-flash` `kimi-k3` `qwen3.8-max` |
| 缓存读 + 写 | 再配 `cache_write` | `gpt-5.6-luna` `gpt-5.6-terra` `gpt-5.6-sol` `gpt-6-astra` |
| 缓存读 + 5 分钟写 + 1 小时写 | 再配 `cache_write_1h` | `claude-opus-5` `claude-sonnet-5` `claude-fable-5` `claude-fable-5-1` |
| 时段缓存价 | `text_schedule` 各时段带 `cache_read` | `deepseek-v4-pro` `deepseek-v4-flash` |

### 自动缓存与显式缓存

**自动缓存**由上游决定是否命中，调用方不传任何参数：命中的 token 出现在
`usage.prompt_tokens_details.cached_tokens` 里，按该型号的缓存读价计费。是否命中不做保证，
成本预估不要按「必定命中」算。

**显式缓存**要在请求里用 `cache_control` 标出可复用的前缀，网关按型号放行：

| 型号 | 显式 `cache_control` |
|---|---|
| `claude-opus-5` `claude-sonnet-5` `claude-fable-5` `claude-fable-5-1` | ✅ 放行，三档缓存价齐备（读 / 5 分钟写 / 1 小时写） |
| 所有 `gemini-*`、`qwen3.8-max` | ❌ 预扣前拒绝：这两家显式缓存与自动缓存的读价不同，两套计费维度尚未同时配齐，只开放自动缓存 |
| 两项计价型号 | ❌ 预扣前拒绝：没有缓存计费维度 |
| 其余（`gpt-5.4/5.5/5.6-*`、`gpt-6-astra`、`grok-4.6`、`kimi-k3`、`deepseek-v4-*`） | 上游只有自动缓存，不需要也不用传 `cache_control` |

被拒绝的请求返回 HTTP 400，**在额度预扣前发生，不计费**。

<Note>
显式缓存的计费维度已配齐、网关已放行，但**缓存命中与 TTL 写入尚未完成验收实测**。
首次接入请用小请求核对一遍控制台用量记录里的缓存分项，再放量。
</Note>

### Claude 显式缓存写法

OpenAI 兼容接口：`content` **必须是内容块数组**，字符串形式的 `content` 带不了 `cache_control`，
标记会被忽略、整段按普通输入计费。

```json
{
  "model": "claude-sonnet-5",
  "max_tokens": 1024,
  "messages": [
    {
      "role": "system",
      "content": [
        {
          "type": "text",
          "text": "这里放要反复复用的长前缀……",
          "cache_control": {"type": "ephemeral"}
        }
      ]
    },
    {"role": "user", "content": "基于上面的内容回答。"}
  ]
}
```

原生 [Messages 接口](/cn/api-reference/text/claude-messages)把前缀放在 `system` 数组里，写法相同。
`ttl` 省略时为 5 分钟；要用 1 小时档，请求里写 `"cache_control": {"type": "ephemeral", "ttl": "1h"}`
并带上 `anthropic-beta: extended-cache-ttl-2025-04-11` 请求头——该头由网关原样透传到上游。

### 命中条件与读数

- **前缀要够长**：通常至少约 1,024 token，短前缀不会产生缓存。
- **前缀要逐字节一致**：文本、空格、换行、内容块顺序有任何差异都不算命中。
- **要在 TTL 内**：5 分钟或 1 小时从最近一次命中重新计时。

Chat 响应里 `usage.prompt_tokens_details.cached_tokens` 是命中量；原生 Messages 用
`cache_read_input_tokens` 与 `cache_creation_input_tokens`，并且原生的 `input_tokens`
**不含**这两项，总输入是三者相加（Chat 的 `prompt_tokens` 则已经含在内）。写入量按缓存写价计费，
比普通输入贵，所以显式缓存只在「前缀稳定且会在 TTL 内被复用」时才划算。

## 当前不开放的能力

以下请求在**额度预扣前**被拒绝（HTTP 400，不计费），因为它们的额外收费维度还没在文本价格契约里表示出来：

- **厂商内置工具**——`tools` 里出现 `function` / `custom` 之外的类型（内置联网、托管搜索、托管执行等）。由调用方自己执行的函数工具不在此列，正常使用。
- **`web_search_options`**。
- **`service_tier`** 取 `standard` / `default` 以外的值。
- **显式缓存**——见上一节的放行表。

此外，模型组会声明本路由实测支持的协议与能力：请求打到未声明的协议（Chat / Responses / Claude Messages / Gemini 原生），或者在明确声明不支持工具 / 结构化输出的型号上传 `tools`、`tool_choice`、`response_format`，同样在预扣前拒绝。各型号支持什么以上面的模型目录为准。

## 目录接口

模型的实时可用性、价格配置和能力字段以目录接口为准，文档更新会滞后于目录：

```bash
curl https://www.qingbo.dev/v1/models \
  -H "Authorization: Bearer $WAVE_API_KEY"
```

单个模型：`GET /v1/models/{model}`。返回的 `price_config` 就是本页表格的来源：`input` / `output` 是基础单价，`cache_read` / `cache_write` / `cache_write_1h` 表示该型号开放到哪一档缓存，`input_tier_threshold` 与 `*_above_price` 是长上下文分档，`cache_billing: "input_output"` 表示只有输入输出两项计价。

旧目录中的模型不自动代表已上架；2024 年 9 月以前发布或已经退役的模型不在新目录中开放。
