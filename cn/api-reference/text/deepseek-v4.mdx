title: "DeepSeek V4 Pro / Flash"
description: "按请求开始时段计价，缓存替代输入计费"
---

使用 `deepseek-v4-pro` 或 `deepseek-v4-flash` 调用统一的 `POST /v1/chat/completions`。切换模型只改 `model`，无需为不同渠道换 URL。

## 时段价格

2026-09-05 核对，单位 USD / 100 万 tokens。下面全部使用 **UTC**；北京时间加 8 小时。

| 时段 | Pro 输入 | Pro 缓存命中 | Pro 输出 | Flash 输入 | Flash 缓存命中 | Flash 输出 |
|---|---:|---:|---:|---:|---:|---:|
| 周一至周五 01:00–04:00、06:00–10:00 | 1.188 | 0.044 | 3.564 | 0.396 | 0.014 | 1.188 |
| 每天 00:00–14:00 内除上述时段 | 0.660 | 0.022 | 1.980 | 0.220 | 0.007 | 0.660 |
| 每天 14:00–24:00 | 0.594 | 0.022 | 1.782 | 0.198 | 0.007 | 0.594 |

区间包含开始、不包含结束，例如周一 04:00 UTC 已进入下一档。**请求开始时确定价格，预扣、响应费用和最终结算使用同一份冻结价格**，即使响应跨过时段边界也不重新选价。报价接口反映报价时刻，不锁定稍后请求的价格。

售价按各项官方价九折或官方原价制定，最高不超过[官方对应时段价格](https://api-docs.deepseek.com/quick_start/pricing/)。公开模型详情 `price_config.text_schedule` 提供完整时段表；后台账务详情可查看实际选中的版本、时段和时间。

缓存命中 tokens 包含在输入总量中，以缓存价替代对应普通输入价，不重复收费。输出含思考 tokens 时只计一次。当前渠道明确不支持独立缓存写入，因此不配置或宣传缓存写入价格。

## 验证范围

- `deepseek-v4-pro`: chat_nonstream, chat_stream, chat_json_schema, chat_nonstream_forced_function.
  Pro 已实测命中 1,024 个缓存 tokens；同一输入从 354 降至 27 quota，缓存计价与账本一致。
- `deepseek-v4-flash`: chat_nonstream, chat_stream, chat_json_schema, chat_nonstream_forced_function.
  Flash 两次重复上下文未观察到缓存命中，缓存价已配置但不保证命中。

本轮测试显式设置 `thinking.type=disabled`。默认思考模式、极限上下文、图像输入、原生 Anthropic/Responses 以及多轮工具调用尚未验收；不会因为官方支持就自动宣称当前渠道已支持。Pro 渠道声明输入 1,000,000、输出 393,216；Flash 为输入 128,000、输出 16,000，未实测同时用满。

## 示例

```bash
curl http://localhost:40081/v1/chat/completions \
  -H "Authorization: Bearer $WAVEAPI_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"deepseek-v4-flash","messages":[{"role":"user","content":"Reply with the single word OK."}],"thinking":{"type":"disabled"},"max_tokens":128,"stream":false}'
```

流式请求设置 `stream:true` 与 `stream_options:{"include_usage":true}`，读取末尾 usage 后再核对最终费用。使用 Key 的有限额度控制预算。
