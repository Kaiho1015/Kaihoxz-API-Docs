Grok 4.20 的非推理版本，适合日常对话、文本改写、信息抽取和分类。直接生成回答，也支持流式输出、JSON Schema 和供应用执行的函数调用参数。

统一使用 `POST /v1/chat/completions`，将 `model` 设为 `grok-4.20-0309-non-reasoning`。

官方发布日期：[2026-03-10](https://docs.x.ai/developers/release-notes)。

## 价格与计费

| 输入总 token 数 | 输入单价 | 输出单价 |
|---|---:|---:|
| < 200,000 | 1.125 | 2.25 |
| ≥ 200,000 | 2.25 | 4.5 |

输入总量达到 200,000 token 时，整单输入和输出使用高档价格；不是只给超出部分加价。这个阈值是当前计价配置，不是模型上下文上限，也不表示已进行同等长度的真实调用。

输入总 token 包括响应中报告的缓存统计，均按普通输入单价计费；缓存统计是输入的组成部分，不再重复相加。本接入仅提供输入、输出两项计价，不提供独立缓存折扣、缓存创建或存储能力。

显式 `cache_control` 请求会在额度预扣前拒绝。

`completion_tokens` 已包含其明细里的思考 token，不要再次相加。缺少 usage 不代表零费用。

```text
USD = (total_input_tokens * applicable_input_rate
     + completion_tokens * applicable_output_rate) / 1,000,000
```

上述公式以完整 usage 为前提。网关先换算基础 quota；启用单请求最小额度规则时，有正用量且计算结果不足 1 基础 quota 的请求先按 1 计，再应用账户分组倍率并取整数。当前验收使用的标准分组倍率为 1，因此正用量单次最低计费 1 quota。1 quota 对应的美元金额由网关换算配置决定，不是固定美元价格；极小请求的实际扣费可能高于公式中的未取整金额。

响应中的 `usage.cost` 是额度整数，不能当成美元；以控制台用量记录核对。

## 支持的能力

- 文本生成与流式输出
- JSON Schema 结构化输出
- 函数调用参数生成，由你的应用执行工具

当前提供文本 Chat 接口。图像输入、内置搜索和多智能体功能不在此接入范围内。

## 调用示例

将 `WAVE_API_KEY` 设为本人 Key。示例明确设置非流式和 512 token 请求预算，不额外设置推理参数。

```bash
curl http://localhost:40081/v1/chat/completions \
  -H "Authorization: Bearer $WAVE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
  "model": "grok-4.20-0309-non-reasoning",
  "messages": [
    {
      "role": "user",
      "content": "Reply with one short greeting."
    }
  ],
  "stream": false,
  "max_tokens": 512
}'
```

按实际部署替换网关地址。`max_tokens=512` 是示例请求参数，不是上下文/输出能力上限，也不是总费用保证。连接中断或缺少最终 usage 时，先检查已有用量记录，勿据此自动重发。
