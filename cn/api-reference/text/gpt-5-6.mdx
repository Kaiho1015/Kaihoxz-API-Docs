### 缓存和思考 token

在统一输入总量中，缓存读取和缓存写入分别替换普通输入计费。缓存写入价为本档普通输入价的 1.25 倍，**不是先收一遍普通输入，再加 1.25 倍写入费**。官方语义见[提示缓存说明](https://developers.openai.com/api/docs/guides/prompt-caching)。

```text
P = 输入总量（含缓存读取和写入）
R = 实际缓存读取 token
W = 实际缓存写入 token
O = 输出总量（已含思考 token）

普通输入 token = P - R - W
费用（USD）= ((P - R - W) × 本档输入价
            + R × 本档缓存读取价
            + W × 本档缓存写入价
            + O × 本档输出价) / 1,000,000
```

`completion_tokens` 已包含 `completion_tokens_details.reasoning_tokens`，思考用量不能再加一次。各分项费用先汇总，再换成整数 quota；账户适用的计费倍率与整数计量也会影响最终额度。

缓存价格适用于渠道实际报告的用量。Luna 已完成自动缓存写入、缓存命中和超过 272K 输入的真实计费验收。Terra / Sol 的缓存，以及所有型号的显式缓存控制参数和保留时长仍未验证；不要从有价格推断这些能力已开放。若用量存在不同保留时长的写入分项，必须使用相应已配置价格，不能把未知时长或缺失价格按零计费。

### `usage.cost` 与最终账务

Chat 非流式响应体或流式 usage 末帧中的 `usage.cost` 是本次按用量计算的 **quota 整数**，不是 USD，也不是美元单价。响应出现该字段不等于账户结算已经完成；最终费用以该调用的账务记录为准。

| 文本账务状态 | 含义 |
|---|---|
| `reserved` | 已预扣，结果尚未确认；预扣不是最终费用 |
| `pricing_pending` | 已收到用量，但价格或计量信息需要核对；保留预扣，不发布确定的费用 |
| `settlement_pending` / `refund_pending` | 等待结算或退款完成 |
| `settled` / `refunded` | 扣费或退款已完成；使用最终账务金额核对 |

这些是文本账务记录的状态，不是 Chat 响应新增的 `billing_status` 字段，也不是异步媒体任务。若没有收到完整 usage、费用缺失或连接中断，不要视为免费或立即重复提交；先核对已有调用及账务状态。缺少可核实的写入价格时，网关不会把供应商返回的同名 USD `cost` 当成 quota 透传。

## Chat 接入

设置 `WAVE_API_KEY` 为自己的 WaveAPI Key。示例使用 Luna；可以把 `model` 换为另外两个公开 ID，参数是否通过以下方验收范围为准。

<CodeGroup>

```bash 非流式
curl https://www.qingbo.dev/v1/chat/completions \
  -H "Authorization: Bearer $WAVE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-5.6-luna",
    "messages": [{"role": "user", "content": "Reply with one short greeting."}],
    "max_completion_tokens": 128,
    "reasoning_effort": "none",
    "stream": false
  }'
```

```bash 流式
curl -N https://www.qingbo.dev/v1/chat/completions \
  -H "Authorization: Bearer $WAVE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-5.6-luna",
    "messages": [{"role": "user", "content": "Reply with one short greeting."}],
    "max_completion_tokens": 128,
    "reasoning_effort": "none",
    "stream": true,
    "stream_options": {"include_usage": true}
  }'
```

</CodeGroup>

`128` 是本轮短文本验证的输出预算，不是模型上限。示例沿用已验证的 `reasoning_effort: "none"`；默认推理行为及其他推理档位尚未验证。开启思考后，思考也会占用输出预算；`finish_reason: "length"` 表示输出可能尚未完成，不能当作完整回答验收。

### 安全读取 SSE 用量末帧

usage 末帧的 `choices` 可以为空数组。先读用量，再判断文本增量，避免在生成已完成后因数组越界丢掉费用信息。

```python
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["WAVE_API_KEY"],
    base_url="https://www.qingbo.dev/v1",
)
stream = client.chat.completions.create(
    model="gpt-5.6-luna",
    messages=[{"role": "user", "content": "Reply with one short greeting."}],
    max_completion_tokens=128,
    reasoning_effort="none",
    stream=True,
    stream_options={"include_usage": True},
)

for chunk in stream:
    if chunk.usage is not None:
        quota_cost = getattr(chunk.usage, "cost", None)
        if quota_cost is not None:
            print(f"\n本次计算额度: {quota_cost} quota")
    if chunk.choices:
        content = chunk.choices[0].delta.content
        if content:
            print(content, end="", flush=True)
```
