QWave API supports many video generation models, **all called through the unified async task endpoint** `/v1/tasks`. Video generation typically takes from 10 seconds up to several minutes; after submission you receive a `task_id`, and you fetch the result via polling or a webhook callback.

## Request Endpoint

```
POST https://www.qingbo.dev/v1/tasks
```

For the full async flow see [Task System](/en/docs/task-system) — Submit → Status → Result + optional webhook.

## Common Parameters (shared across the series)

> Each model's actual supported range differs — **see the individual vendor docs**.

<ParamField body="model" type="string" required>
  Model ID (group_name); pick from the vendor docs above
</ParamField>

<ParamField body="action" type="string" default="generate">
  `generate` — the only action this model takes.

  **The mode is decided by what you send, not by the action:** `prompt` alone is text-to-video; `image_urls` is image-to-video; `first_frame_image` + `last_frame_image` is a first/last-frame transition; `video_urls` / `audio_urls` is reference-to-video.
</ParamField>

<ParamField body="prompt" type="string">
  Video description text. Required for T2V; optional as guidance for other modes
</ParamField>

<ParamField body="duration" type="integer">
  Video duration in seconds; range depends on the model
</ParamField>

<ParamField body="aspect_ratio" type="string">
  Frame aspect ratio, e.g. `16:9` / `9:16` / `1:1`
</ParamField>

<ParamField body="resolution" type="string">
  Output resolution, e.g. `720p` / `1080p` / `4K`
</ParamField>

<ParamField body="image_urls" type="string[]">
  Array of reference image URLs (used for I2V / R2V)
</ParamField>

<ParamField body="first_frame_image" type="string">
  First-frame image URL (used for first/last-frame mode)
</ParamField>

<ParamField body="last_frame_image" type="string">
  Last-frame image URL; must be paired with `first_frame_image`
</ParamField>

<ParamField body="video_urls" type="string[]">
  Array of reference video URLs — **a single element is sufficient** (used for video continuation / R2V video reference / video editing)

  <Note>
  **Reference-video billing differs by vendor** — see each model page, and [Input video duration and billing](#input-video-duration-and-billing) below.
  </Note>
</ParamField>

<ParamField body="audio_urls" type="string[]">
  Array of reference audio URLs — **a single element is sufficient** (used for driving audio / custom voiceover)
</ParamField>

<ParamField body="callback_url" type="string">
  Webhook callback URL, invoked when the task reaches a terminal state. See [Task System](/en/docs/task-system#webhook)
</ParamField>

## Input Video Duration and Billing

Requests that carry `video_urls` (reference video / video editing / motion control) follow these three rules.

**How seconds are counted** — the gateway reads the video's file header for its real duration and **truncates to whole seconds** (10.9 seconds counts as 10); anything under 1 second counts as 1. This matches the upstream's own accounting.

**What happens if it cannot be read** — if the header cannot be parsed (unusual format, unreachable URL, and so on) the request is **rejected** with `400 input_video_duration_unknown` and **nothing is charged** — it is not estimated at a cap and billed. Use a directly downloadable URL in a common container format (mp4 / webm).

**Estimating before you submit** — `POST https://www.qingbo.dev/waveapi/quote` with `video_urls` returns the exact price for that call, including the input seconds it probed.

This is a **public utility endpoint and needs no API key**. It replies in the standard envelope `{code, message, data}`, where `data` carries:

| Field | Meaning |
|---|---|
| `total_usd` | Total price for this call, in USD |
| `unit` | Billing unit (seconds / images / characters, and so on) |
| `billed_quantity` | The quantity actually billed — the probed input-video seconds show up here |
| `multipliers` | Multipliers in effect (user-group ratio and the like) |

When a request is rejected, `errorKey` carries the specific reason (such as `input_video_duration_unknown`) and `message` holds text you can show to the user directly.

How the reference video then enters the price (counted as seconds, only switching tier, or replacing the clip price) depends on the vendor — see the billing section on each model page.

## Submit Response Example

```json
{
  "task_id": "task-wave1775285160b950328499",
  "model": "veo3.1-quality",
  "action": "generate",
  "status": "queued",
  "created_at": 1775285160040,
  "progress": 0
}
```

After receiving `task_id`, poll [`GET /v1/tasks/{task_id}`](/en/api-reference/task/status) until `status = completed`, then read the video URL.

## Mode Quick Reference

| Mode | Trigger Fields | Typical Vendors |
|---|---|---|
| **Text-to-video (T2V)** | `prompt` only | All vendors that support the generate action |
| **Image-to-video (I2V)** | `+ first_frame_image` or `image_urls` (single image) | Seedance / Kling / Hailuo / Vidu / Wan / Veo / SkyReels / Grok / HappyHorse / FLUX 3 Video / Omni |
| **First/last frame** | `first_frame_image + last_frame_image` (Kling takes two images in `image_urls`) | Seedance / Kling / Veo / Vidu / SkyReels / Hailuo 02 / Wan 3.0 / Gemini Omni 1.1 Flash |
| **Reference-to-video (R2V)** | `image_urls` (multiple) | Seedance / Kling Omni / Vidu / SkyReels / HappyHorse / Wan 2.7 R2V / Omni |
| **Video reference (R2V video)** | `+ video_urls` (reference video) | Seedance 2.x / Kling / SkyReels / Wan / MiniMax H3 / Omni |
| **Video continuation** | `video_urls` (single clip) or `ref_task_id` | Omni / FLUX 3 Video / Veo reverse tiers (`extend`) / Seedance 2.5 (`extend`) |
| **Video editing (EDIT)** | `video_urls + prompt` (optionally `image_urls` as style reference) | Wan VideoEdit / HappyHorse 1.0 / Seedance 2.5 / Kling v3 Omni · Video O1 |
| **Audio reference** | `+ audio_urls` | HappyHorse / Wan / SkyReels / Seedance 2.x / MiniMax H3 |

<Note>
Not every model supports every mode — check each vendor's doc for the actual supported `action` list and field range. The backend validates whether request fields fall within the vendor's declared capabilities and returns an error if they do not.
</Note>

## Field Naming Conventions

- **Media references are always plural** — always `image_urls` / `video_urls` / `audio_urls`; even a single video uses a one-element array `["one.mp4"]`
- **Frame ratio is unified as** `aspect_ratio` — vendor-internal `size` / `ratio` etc. are implementation details and not exposed
- **Resolution is unified as** `resolution` — vendor-internal `mode` / `quality` etc. are implementation details
- **First/last-frame fields carry the `_image` suffix** — `first_frame_image` / `last_frame_image` (emphasizing the image resource)
