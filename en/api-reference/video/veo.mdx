Google's Veo 3.1 video line comes in two routes. The official route, `veo3.1-fast` and `veo3.1-quality`, offers 4 / 6 / 8 second output, first and last frames, native audio and `seed`, billed per second. The economy route, `veo3.1-lite`, `veo3.1-fast-rev` and `veo3.1-quality-rev`, reaches Veo through an aggregator, always outputs eight seconds and is billed per finished clip; the two `-rev` tiers can also extend a video they generated earlier. The two routes differ in both parameters and billing, and never switch to each other.

## Quick start

<CodeGroup>

```bash Text to video (official)
curl -X POST https://www.qingbo.dev/v1/tasks \
  -H "Authorization: Bearer $WAVE_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: veo-demo-001" \
  -d '{
    "model": "veo3.1-fast",
    "action": "generate",
    "prompt": "Aerial sunrise over snow peaks, clouds rolling, slow push in",
    "duration": 8,
    "resolution": "1080p",
    "aspect_ratio": "16:9"
  }'
```


A successful submission returns a `task_id`. Retrieve the result with [`GET /v1/tasks/{task_id}`](/en/api-reference/task/status), wait inline with [`Prefer: wait`](/en/api-reference/task/submit#in-request-waiting-prefer-wait), or configure a webhook.

**Chaining an extension** takes two steps. Submit `action: "generate"` on `veo3.1-fast-rev` or `veo3.1-quality-rev` and keep the `task_id`; once that task is `completed`, pass its `task_id` as `ref_task_id` on an `action: "extend"` request. `ref_task_id` is the `task_id` returned by that first task, not an upstream ID, and it must be a completed `generate` task on the same model under the same API key.

## Request parameters

### Both routes

<ParamField body="model" type="string" required>
  Model ID; see Available models.
</ParamField>

<ParamField body="action" type="string" default="generate">
  - `generate` — generate a video; supported by all five models
  - `extend` — continue a finished video; only `veo3.1-fast-rev` and `veo3.1-quality-rev` support it, and `ref_task_id` is required
</ParamField>

<ParamField body="prompt" type="string" required>
  Video description. Under `action: "extend"` it describes the continuation.
</ParamField>

<ParamField body="duration" type="integer">
  Output duration in seconds; required under `action: "generate"`. The official route takes `4`, `6` or `8`, and `resolution: "1080p"` takes `8` only; the economy route is fixed at `8`. `action: "extend"` does not take this parameter — the continuation's length is decided upstream.
</ParamField>

<ParamField body="resolution" type="string" default="720p">
  Output resolution: `720p` or `1080p`.
</ParamField>

<ParamField body="aspect_ratio" type="string" default="16:9">
  Frame ratio: `16:9` or `9:16`.
</ParamField>

### Official route (`veo3.1-fast` / `veo3.1-quality`)

<ParamField body="first_frame_image" type="string">
  First-frame image URL.
</ParamField>

<ParamField body="last_frame_image" type="string">
  Last-frame image URL; must be sent together with `first_frame_image`.
</ParamField>

<ParamField body="negative_prompt" type="string">
  Negative prompt describing what to keep out of the video.
</ParamField>

<ParamField body="seed" type="integer">
  Random seed, for reproducing a result.
</ParamField>

<ParamField body="generate_audio" type="boolean" default="false">
  Generate native audio. Enabling it moves the request to the audio pricing tier.
</ParamField>

<ParamField body="person_generation" type="string">
  Person policy: `allow_adult` allows adult people / `disallow` generates none.
</ParamField>

<ParamField body="resize_mode" type="string">
  How to fit a frame image whose ratio differs from the output: `pad` or `crop`.
</ParamField>

### Economy route (`veo3.1-lite` / `veo3.1-fast-rev` / `veo3.1-quality-rev`)

<ParamField body="image_urls" type="string[]">
  Reference image URLs, supported by `veo3.1-fast-rev` and `veo3.1-quality-rev`; how many depends on `generation_type`. `veo3.1-lite` is text-to-video only and takes no images.
</ParamField>

<ParamField body="generation_type" type="string">
  How the images are used; required whenever `image_urls` is present:

  - `frame` — treat them as first / last frames; 1-2 images
  - `reference` — treat them as reference material; 1-3 images, `veo3.1-fast-rev` only
</ParamField>

<ParamField body="enable_gif" type="boolean" default="false">
  Also output a GIF. Cannot be combined with `resolution: "1080p"`.
</ParamField>

<ParamField body="ref_task_id" type="string" required>
  The parent task being extended; required under `action: "extend"`. Use the `task_id` returned by the `generate` task.
</ParamField>

<ParamField body="raw" type="boolean" default="false">
  Under `action: "extend"`, whether to return only the newly generated segment. `false` returns the joined clip.
</ParamField>

See [Submit a task](/en/api-reference/task/submit) for `callback_url`, `callback_events`, `Prefer: wait`, `Idempotency-Key`, and the maximum-cost header.

The official route does not support `image_urls`, `generation_type`, `enable_gif`, `ref_task_id` or `raw`; the economy route does not support `first_frame_image`, `last_frame_image`, `negative_prompt`, `seed`, `generate_audio`, `person_generation` or `resize_mode`. Any other parameter returns `400` and is not billed.

## Limits

| Models | Condition | Limit |
|---|---|---|
| All | `action: "generate"` | Generation requires prompt and duration. |
| `veo3.1-fast`, `veo3.1-quality` | `last_frame_image` provided | A last frame requires a first frame. |
| `veo3.1-fast`, `veo3.1-quality` | `resolution: "1080p"` | 1080p requires an 8 second duration. |
| `veo3.1-fast-rev`, `veo3.1-quality-rev` | `action: "generate"` | Reverse generation is fixed at eight seconds. |
| `veo3.1-fast-rev`, `veo3.1-quality-rev` | `action: "extend"` | Extend accepts a parent task, prompt and raw only. |
| `veo3.1-fast-rev`, `veo3.1-quality-rev` | `image_urls` provided | generation_type is required with images. |
| `veo3.1-fast-rev`, `veo3.1-quality-rev` | `generation_type: "frame"` | Frame mode accepts one or two images. |
| `veo3.1-fast-rev` | `generation_type: "reference"` | Reference mode accepts up to three images. |

| Item | Models | Maximum |
|---|---|---|
| Reference images | `veo3.1-fast-rev` | 3 |
| Reference images | `veo3.1-quality-rev` | 2 |
| Reference images | `veo3.1-lite` | No images |
| Frame images | `veo3.1-fast`, `veo3.1-quality` | 1 first frame + 1 last frame |
| Duration | `veo3.1-fast`, `veo3.1-quality` | 4 / 6 / 8 seconds, 8 at most |
| Duration | `veo3.1-lite`, `veo3.1-fast-rev`, `veo3.1-quality-rev` | Fixed at 8 seconds |

The `ref_task_id` on `action: "extend"` must point at a completed `generate` task on the same model. Pointing at another model, another action or an unfinished task returns `400` and is not billed.

## Pricing

The two routes are billed differently; read this section before choosing a model.

### Official route

`veo3.1-fast` and `veo3.1-quality` are billed **resolution tier × seconds**: `resolution` picks the tier (`720p` or `1080p`), and the seconds come from `duration` (`4`, `6` or `8`).

`generate_audio: true` switches to the audio tier's per-second rate, still multiplied by `duration` alone. Both resolutions have an audio tier. Frame images, `negative_prompt` and `seed` do not affect the price.

### Economy route

`veo3.1-lite`, `veo3.1-fast-rev` and `veo3.1-quality-rev` are billed **per finished clip**: one charge per generation, independent of length (output is always eight seconds). Resolution is the only tiering dimension; the number of reference images and the `generation_type` do not affect the price.

`action: "extend"` is also one charge per finished clip, independent of how long the continuation is; `raw` does not affect the price either.

<Note>
Per-model rates are in `price_config` on `GET /v1/models`, and in the console's Model Market.

What a single call actually cost is the `cost` field on the task response — an integer quota at 500,000 quota = 1 USD.
</Note>

You are only billed for a successfully generated video. Failed and cancelled tasks, and tasks that return no usable video, are refunded in full. The final charge is the `cost` field on the task response — an integer quota, not dollars.

## Available models

**Official route** — billed per second, with frame control and native audio.

| Model ID | Duration | Resolution | Image input | Native audio |
|---|---|---|---|---|
| `veo3.1-fast` | 4 / 6 / 8s | `720p` `1080p` (1080p is 8s only) | First + last frame | Yes |
| `veo3.1-quality` | 4 / 6 / 8s | `720p` `1080p` (1080p is 8s only) | First + last frame | Yes |

**Economy route** — one price per finished clip, always eight seconds, no native audio.

| Model ID | Actions | Resolution | Image input | GIF |
|---|---|---|---|---|
| `veo3.1-lite` | `generate` | `720p` `1080p` | None | `enable_gif` |
| `veo3.1-fast-rev` | `generate` `extend` | `720p` `1080p` | `frame` 1-2 / `reference` 1-3 | `enable_gif` |
| `veo3.1-quality-rev` | `generate` `extend` | `720p` `1080p` | `frame` 1-2 | `enable_gif` |
