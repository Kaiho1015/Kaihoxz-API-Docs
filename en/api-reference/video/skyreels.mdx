SkyReels V4 is a unified multimodal video-and-audio generation model that jointly produces synchronized picture and sound from text, image and video inputs, at 480p to 1080p and 3 to 15 seconds. This page covers `skyreels-v4-fast` and `skyreels-v4-std`: both tiers expose the same action, parameters and value ranges — Fast is the speed-optimized configuration, Std is the default quality configuration — so switching tiers means changing `model`. Every request is submitted asynchronously through `POST /v1/tasks`.

## Quick start

<CodeGroup>

```bash Text to video
curl -X POST https://www.qingbo.dev/v1/tasks \
  -H "Authorization: Bearer $WAVE_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: skyreels-demo-001" \
  -d '{
    "model": "skyreels-v4-fast",
    "action": "generate",
    "prompt": "A shiba inu in a spacesuit walking on the moon, the camera pushing in slowly",
    "duration": 5,
    "resolution": "1080p",
    "aspect_ratio": "16:9"
  }'
```

```bash First and last frame
curl -X POST https://www.qingbo.dev/v1/tasks \
  -H "Authorization: Bearer $WAVE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "skyreels-v4-std",
    "action": "generate",
    "prompt": "She walks toward the camera, hair moving in the wind",
    "first_frame_image": "https://cdn.example.com/first.jpg",
    "end_frame_image": "https://cdn.example.com/last.jpg",
    "duration": 8,
    "resolution": "1080p"
  }'
```

```bash Reference video
curl -X POST https://www.qingbo.dev/v1/tasks \
  -H "Authorization: Bearer $WAVE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "skyreels-v4-fast",
    "action": "generate",
    "prompt": "Follow the camera motion in @video_1, but set it on a snowy mountain",
    "video_urls": ["https://cdn.example.com/source.mp4"],
    "resolution": "720p"
  }'
```

```bash Reference image (character consistency)
curl -X POST https://www.qingbo.dev/v1/tasks \
  -H "Authorization: Bearer $WAVE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "skyreels-v4-std",
    "action": "generate",
    "prompt": "@Actor-1 walks through a neon-lit street at night, the camera tracking sideways",
    "ref_images": [
      {
        "tag": "@Actor-1",
        "type": "image",
        "image_urls": ["https://cdn.example.com/actor-a.jpg"]
      }
    ],
    "duration": 6,
    "resolution": "1080p"
  }'
```

</CodeGroup>

A successful submission returns a `task_id`. Retrieve the result with [`GET /v1/tasks/{task_id}`](/en/api-reference/task/status), wait inline with [`Prefer: wait`](/en/api-reference/task/submit#in-request-waiting-prefer-wait), or configure a webhook.

## Request parameters

<ParamField body="model" type="string" required>
  Either `skyreels-v4-fast` or `skyreels-v4-std`.
</ParamField>

<ParamField body="action" type="string" default="generate">
  `generate` is the only action in this series. The mode follows the media fields you send: `prompt` alone is text-to-video; `first_frame_image`, `end_frame_image` or `mid_frame_images` is image-to-video; `ref_images` or `video_urls` is reference-driven generation. Image-to-video fields and reference fields cannot be combined.
</ParamField>

<ParamField body="prompt" type="string" required>
  The video description. When you send `video_urls`, `ref_images` or `mid_frame_images`, the prompt must contain the matching `@` tag.
</ParamField>

<ParamField body="duration" type="integer">
  Video length in seconds, an integer from `3` to `15`. Ignored when `video_urls` is present — the output follows the reference video.
</ParamField>

<ParamField body="resolution" type="string">
  Output resolution: `480p`, `720p` or `1080p`. Only `480p` and `720p` are available when `video_urls` is present.
</ParamField>

<ParamField body="aspect_ratio" type="string">
  Frame ratio: `16:9`, `9:16`, `1:1`, `4:3` or `3:4`. Ignored when a first/end frame image or a reference video is present — the ratio follows the input material.
</ParamField>

<ParamField body="video_urls" type="string[]">
  Reference video URLs, used as motion and subject reference. The Nth entry gets the tag `@video_N`, which the prompt must reference (for example `Follow the camera motion in @video_1`); without it the upstream rejects the request and nothing is billed.
</ParamField>

<ParamField body="first_frame_image" type="string">
  Starting frame image URL (jpg / jpeg / png / gif / bmp).
</ParamField>

<ParamField body="end_frame_image" type="string">
  Closing frame image URL; combine with the first frame for start/end control.
</ParamField>

<ParamField body="mid_frame_images" type="object[]">
  Mid keyframe list, up to 6 entries, available in image-to-video mode only. Each entry holds:

  - `tag`: a tag starting with `@` that must appear in the prompt
  - `image_url`: the image URL
  - `time_stamp`: the moment it appears, in seconds. `-1` (the default) leaves it unspecified; otherwise `0 < time_stamp < duration`
</ParamField>

<ParamField body="ref_images" type="object[]">
  Reference image list, available in reference mode only and mutually exclusive with the image-to-video fields. All entries must share the same `type`. Each entry holds:

  - `tag`: a tag starting with `@` that must appear in the prompt
  - `type`: `image` for an ordinary reference image, `grid` for a single image composed of several tiles
  - `image_urls`: an array of image URLs
  - `audio_url`: a voice audio URL, allowed only when `type` is `image`, up to 15 seconds
</ParamField>

<ParamField body="prompt_optimizer" type="boolean" default="true">
  Whether to auto-optimize the prompt before generation.
</ParamField>

See [Submit Task](/en/api-reference/task/submit) for `callback_url`, `callback_events`, `Prefer: wait`, `Idempotency-Key` and the maximum-cost header.

Any other parameter returns `400` and is not billed.

## Limits

- With reference video: duration follows the reference (max 10s), resolution limited to 480p/720p
- This model produces one result per task; n is not supported

| Item | Limit |
|---|---|
| Duration `duration` | 3 to 15 seconds; follows the reference video, capped at 10 seconds, when `video_urls` is present |
| Resolution `resolution` | `480p` / `720p` / `1080p`; only `480p` / `720p` when `video_urls` is present |
| Reference video `video_urls` | 1 clip, 1 to 10 seconds, MP4 / MOV |
| Mid keyframes `mid_frame_images` | Up to 6 entries |
| Reference images `ref_images` | `type: image`: 1 to 3 entries with 1 to 5 images each; `type: grid`: 1 entry with 1 image |
| Mutually exclusive | `first_frame_image` / `end_frame_image` / `mid_frame_images` cannot be combined with `ref_images` / `video_urls` |

All input material must be publicly downloadable over HTTP(S).

## Pricing

Billing is **resolution tier × output seconds**, where the seconds come from the `duration` you send. The three resolutions are priced separately, and every `skyreels-v4-std` tier sits above the matching `skyreels-v4-fast` tier.

Sending `video_urls` switches tiers: the output seconds settle at the **reference-video tier**, which is above the ordinary tier at the same resolution, and the reference video's own length is not billed on top. In this mode the output length follows the reference video (capped at 10 seconds) and only `480p` and `720p` are available.

Reference images (`ref_images`), keyframe images and prompt length carry no separate charge.

<Note>
Rates move with the upstream, so this section describes billing dimensions only and lists no amounts.

Current rates: `price_config` on `GET /v1/models`, or the Model Market in the console.
Actual cost of one call: the `cost` field on the task response (an integer quota; 500,000 quota = 1 USD).
</Note>

You are billed only for a delivered video. Failed and cancelled tasks, and upstream successes that carry no deliverable video, are refunded in full. The final charge is the `cost` field on the task response — an integer quota, not dollars (500,000 quota = 1 USD).

## Response

```json Completed task
{
  "task_id": "task-wave1775285160b950328499",
  "model": "skyreels-v4-fast",
  "action": "generate",
  "status": "completed",
  "progress": "100%",
  "created_at": 1775285160,
  "completed_at": 1775285320,
  "result": {
    "videos": [
      {
        "expires_at": 1775371560,
        "url": ["https://cdn.example.com/result.mp4"]
      }
    ]
  },
  "billing_status": "settled",
  "cost": 61875,
  "urls": {
    "get": "https://www.qingbo.dev/v1/tasks/task-wave1775285160b950328499",
    "cancel": "https://www.qingbo.dev/v1/tasks/task-wave1775285160b950328499/cancel"
  }
}
```

Generated videos are returned in `result.videos`, with picture and audio in the same file; `url` is an array and `expires_at` is the link expiry in Unix seconds, so copy the file to your own storage before then. See [Query Task Status](/en/api-reference/task/status) for the full field reference.

## Available models

| Model ID | Resolution | Duration (s) | Action | Notes |
|---|---|---|---|---|
| `skyreels-v4-fast` | `480p` / `720p` / `1080p` | Any integer 3 to 15 | `generate` | Speed-optimized configuration, trading some fidelity for quicker generation |
| `skyreels-v4-std` | `480p` / `720p` / `1080p` | Any integer 3 to 15 | `generate` | Default quality configuration, prioritizing full fidelity |
