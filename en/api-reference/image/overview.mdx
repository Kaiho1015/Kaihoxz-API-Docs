QWave API supports multiple image generation models, **all called through the unified async task endpoint** `/v1/tasks`. Image generation typically completes in 1-30 seconds. After submission, you receive a `task_id` and retrieve results via polling or webhook callback.

## Endpoint

```
POST https://www.qingbo.dev/v1/tasks
```

For the async flow, see [Task System](/en/docs/task-system) — Submit → Status → Result + optional webhook.

## Two request paths

Images have two entries. Billing is identical on both; they differ in parameter validation and how results come back:

| | `POST /v1/tasks` | `POST /v1/images/generations` · `/v1/images/edits` |
|---|---|---|
| Result | Async — you get a `task_id` and poll (or wait inline with `Prefer: wait`) | Sync — the image comes back in the response |
| Request shape | This platform's unified fields: `action` / `aspect_ratio` / `resolution` / `image_urls` | OpenAI's native shape: `size` / `quality` / `n` / `response_format` |
| Validation | **Full** — action, aspect ratio, resolution, quality and reference-image count are all checked; a non-conforming request returns `400` and is not billed | The compatibility layer does not run these checks, so invalid parameters are not caught up front |
| Use it for | New integrations, and anything needing masked inpainting, quality tiers, resolution tiers or multi-image references | Existing OpenAI SDK projects — point `base_url` at us and go |

<Note>
To migrate with the OpenAI SDK, set `base_url` to `https://www.qingbo.dev/v1` and change `model` to one of our model IDs.
Model-specific capabilities (the `mask_url` mask, the `1k` / `2k` / `4k` resolution tiers, reference-image limits and so on)
follow the task API documentation — the parameters on our model pages describe the task API.
</Note>

## Common Parameters (shared across models)

> Actual support varies per model — **see each vendor doc for details**.

<ParamField body="model" type="string" required>
  Model ID (group_name); pick one from the vendor docs above
</ParamField>

<ParamField body="action" type="string" default="generate">
  - `generate` — text to image (default)
  - `edit` — image editing; pair with `image_urls`

  **The mode is decided by what you send, not by the action:** `prompt` alone is text-to-image; one `image_urls` entry is image-to-image; several are multi-image reference; add `mask_url` for inpainting.
</ParamField>

<ParamField body="prompt" type="string" required>
  Image description text; supports both Chinese and English
</ParamField>

<ParamField body="n" type="integer" default="1">
  Number of images to generate (some vendors cap per-call count)
</ParamField>

<ParamField body="seed" type="integer" default="-1">
  Random seed; `-1` means random. A fixed value reproduces similar results.
</ParamField>

<ParamField body="aspect_ratio" type="string">
  Aspect ratio, e.g. `16:9` / `9:16` / `1:1`. Some vendors support `auto` (smart selection).
</ParamField>

<ParamField body="resolution" type="string">
  Output resolution, e.g. `1K` / `2K` / `4K`. Supported range varies per vendor.
</ParamField>

<ParamField body="image_urls" type="string[]">
  Reference image URL array (for image-to-image / multi-image reference)
</ParamField>

<ParamField body="callback_url" type="string">
  Webhook callback URL, invoked when the task reaches a terminal state. See [Task System](/en/docs/task-system#webhook).
</ParamField>

## Submit Response Example

```json
{
  "task_id": "task-wave1775285160b950328499",
  "model": "seedream-5.0-lite",
  "action": "generate",
  "status": "queued",
  "created_at": 1775285160040,
  "progress": 0
}
```

After receiving the `task_id`, call [`GET /v1/tasks/{task_id}`](/en/api-reference/task/status) to poll until `status = completed`, then read the image URLs.

## Mode Quick Reference

| Mode | Trigger Fields | Typical Vendors |
|---|---|---|
| **Text-to-image (T2I)** | `prompt` only | All |
| **Image-to-image / multi-image reference** | `+ image_urls` (single or multiple) | Seedream / Gemini / GPT Image / Wan / Qwen / FLUX / Grok |
| **Image editing (inpainting / lighting changes)** | `+ image_urls + action: edit` | Seedream / Gemini / GPT Image / Wan / Qwen / FLUX / Grok |
| **Inpainting (with mask)** | `+ image_urls + mask_url + action: edit` | The three [GPT Image official](/en/api-reference/image/gpt-image/overview) models; **not supported** on the Nano Banana economy routes |
| **Sequential image group (thematic set)** | `enable_sequential: true` | Wan Image |
| **Interactive editing (bbox selection)** | `+ image_urls + bbox_list` | Wan Image |

<Note>
Not every model supports every mode — check each vendor doc for the actual `action` list and field range. The backend validates request fields against the vendor's declared capabilities and rejects out-of-range requests.
</Note>

## Field Naming Conventions

- **Media references are always plural** — always `image_urls`, even for a single image use a one-element array `["one.jpg"]`
- **Aspect ratio is unified as** `aspect_ratio` — vendor internals using `size` / `ratio` are implementation details you don't need to track
- **Resolution is unified as** `resolution` — vendor internals using `quality` are implementation details
- **Mask field** `mask_url` (used for GPT Image official inpainting)
