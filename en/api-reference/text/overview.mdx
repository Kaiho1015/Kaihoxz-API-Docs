Every text model on WaveAPI is served through the OpenAI-compatible Chat Completions endpoint: switch models by changing `model` — no per-vendor URLs, keys or upstream knowledge required. This page is the catalog for text: call entry points first, then the billing rules, then model IDs, prices and verified capabilities grouped by vendor.

New integrations should use Chat Completions; the native entries only save migration work for existing clients and expose no extra capability. All entries authenticate with a WaveAPI key (Chat / Responses via `Authorization: Bearer`, Messages via `x-api-key`, Gemini native via `x-goog-api-key`); an ecosystem login token is not a model key — see [Authentication](/en/docs/authentication).

## Billing rules

These rules apply to every text model on this page; model-specific differences live in the Notes column and the paragraph under each vendor table.

- **Unit and source**: prices are USD per 1 million tokens, checked on 2026-09-05. Sale prices are 10% off the official list price or equal to it, never above; Batch, Flex and Priority prices are not used.
- **Total input includes cache**: `prompt_tokens` is total input; reported cache-hit / cache-write tokens are billed at their cache rates, the rest at the ordinary input rate. Cache tokens are part of the total, never an amount added on top.
- **Reasoning is inside output**: `completion_tokens` already includes `completion_tokens_details.reasoning_tokens`; reasoning is billed once at the output rate.
- **Two-rate models**: models whose cache-read column shows `—` bill input and output only; any cache statistics in the response are charged at the ordinary input rate, and explicit `cache_control` is rejected before reservation.
- **Long-context tiers**: models whose price carries a slash pick the tier from **total input (cache included)**; once the threshold is reached the whole request — input, cache and output — moves to the price after the slash, not just the excess. Thresholds and how the exact boundary value is treated are stated per vendor.
- **Time-of-day pricing**: DeepSeek V4 is priced by the UTC slot at request start; see the DeepSeek section.
- **Quota conversion**: the line items are summed and converted to an integer quota at **500,000 quota = 1 USD**; a request with positive usage that rounds below 1 quota is charged 1, then the account group multiplier is applied and the result truncated. `usage.cost` in the response is that integer quota, **not dollars**.

```text
ordinary input tokens = prompt_tokens - cached_tokens - cache_write_tokens
cost (USD) = ( ordinary input tokens × input rate
             + cached_tokens × cache-read rate
             + cache_write_tokens × cache-write rate
             + completion_tokens × output rate ) / 1,000,000
quota      = cost (USD) × 500,000, truncated, minimum 1
```

The final charge is the text ledger entry in your billing records; its states mean:

| Ledger state | Meaning |
|---|---|
| `reserved` | Reserved, result not yet confirmed; the reservation is not the final charge |
| `pricing_pending` | Usage received but price or metering needs review; reservation held, no final cost published |
| `settlement_pending` / `refund_pending` | Waiting for settlement or refund to complete |
| `settled` / `refunded` | Charge or refund completed; reconcile against the final ledger amount |

<Warning>
A missing final `usage`, a dropped connection or a response without a cost field **does not make the call free**. Check the existing usage record in the console before resubmitting; never retry automatically on that basis.
</Warning>

## Not yet available

The following are not wired up for billing yet and are rejected before reservation (HTTP 400, no charge): vendor built-in tools such as hosted web search / hosted execution, `web_search_options`, any `service_tier` other than `standard` / `default`, Gemini explicit caching, and `cache_control` on two-rate models. Client-executed function calling (`tools` + `tool_calls`) is not a built-in tool; use it according to each model's Verified column.

## Catalog API

Live availability, price configuration and capability flags come from the catalog API; this page lags behind it:

```bash
curl https://www.qingbo.dev/v1/models \
  -H "Authorization: Bearer $WAVE_API_KEY"
```

Single model: `GET /v1/models/{model}`. The `price_config` it returns is where this page's tables come from: `input` / `output` are the base rates, `cache_read` / `cache_write` / `cache_write_1h` show how far caching is opened up for that model, `input_tier_threshold` with the `*_above_price` fields is the long-context tier, and `cache_billing: "input_output"` means input and output are the only two rates.

A model present in an old catalog is not automatically live; models released before September 2024 or already retired are not offered in the new catalog.
