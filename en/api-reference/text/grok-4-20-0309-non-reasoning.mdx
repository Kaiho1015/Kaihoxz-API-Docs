The non-reasoning variant of Grok 4.20, suited to everyday conversation, rewriting, information extraction, and classification. It produces answers directly and supports streaming, JSON Schema output, and function-call arguments for your application.

Use `POST /v1/chat/completions` with `model` set to `grok-4.20-0309-non-reasoning`.

Official release date: [2026-03-10](https://docs.x.ai/developers/release-notes).

## Pricing and billing

These are WaveAPI sale prices in **USD per 1 million tokens**. The official reference does not establish support for every official billing feature on this route.

[Official pricing source](https://docs.x.ai/developers/pricing)

| Total input tokens | Input rate | Output rate |
|---|---:|---:|
| < 200,000 | 1.125 | 2.25 |
| ≥ 200,000 | 2.25 | 4.5 |

When total input reaches 200,000 tokens, the entire request uses the higher input and output rates. This is not marginal pricing. The configured threshold is not a context limit or proof of a live request at that length.

Total input includes any reported cache statistics and is billed at the ordinary input rate. Cache statistics are part of input, not an extra amount to add again. This integration offers only input and output billing, with no separate cache discount, cache creation, or storage capability.

Explicit `cache_control` requests are rejected before quota reservation.

`completion_tokens` already includes reasoning tokens in its detail fields; do not add them again. Missing usage does not mean zero cost.

```text
USD = (total_input_tokens * applicable_input_rate
     + completion_tokens * applicable_output_rate) / 1,000,000
```

The formula requires complete usage. The gateway converts it to base quota; with the per-request minimum enabled, a request with positive usage and less than 1 base quota is raised to 1 before applying the account group multiplier and taking the integer part. The verified standard group uses multiplier 1, so its minimum charge for positive usage is 1 quota per request. The USD value of 1 quota depends on gateway conversion settings. A very small request can therefore cost more than the unrounded formula amount.

Response `usage.cost` is an integer quota amount, not USD. Reconcile it with console usage records.

## Supported capabilities

- Text generation and streaming
- Structured output with JSON Schema
- Function-call arguments; your application executes the tool

This integration provides text Chat requests. Image input, built-in search, and multi-agent features are outside its scope.

## Request example

Set `WAVE_API_KEY` to your own key. This example explicitly selects non-streaming and a requested 512-token budget, without adding a reasoning parameter.

```bash
curl http://localhost:40081/v1/chat/completions \
  -H "Authorization: Bearer $WAVE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
  "model": "grok-4.20-0309-non-reasoning",
  "messages": [
    {
      "role": "user",
      "content": "Reply with one short greeting."
    }
  ],
  "stream": false,
  "max_tokens": 512
}'
```

Replace the gateway URL for your deployment. `max_tokens=512` is an example request parameter, not a model limit or total-cost guarantee. If the connection drops or final usage is absent, inspect existing usage records before retrying.
