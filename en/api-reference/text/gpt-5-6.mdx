## Pricing and billing

These standard text prices were checked on September 5, 2026. All rates are in **USD per 1 million tokens**. WaveAPI prices this group at 90% of the corresponding official specification, without using Batch, Flex, or Priority rates.

### Standard tier: total input at or below 272,000 tokens

| Model | Uncached input | Output, including reasoning | Cache reads | Cache writes |
|---|---:|---:|---:|---:|
| Luna | $0.18 | $1.08 | $0.018 | $0.225 |
| Terra | $1.80 | $10.80 | $0.18 | $2.25 |
| Sol | $3.60 | $18.00 | $0.36 | $4.50 |

### Long-context tier: total input above 272,000 tokens

| Model | Uncached input | Output, including reasoning | Cache reads | Cache writes |
|---|---:|---:|---:|---:|
| Luna | $0.36 | $1.62 | $0.036 | $0.45 |
| Terra | $3.60 | $16.20 | $0.36 | $4.50 |
| Sol | $7.20 | $27.00 | $0.72 | $9.00 |

Total input includes cache-read and cache-write tokens. **Exactly 272,000 tokens uses the standard tier. Above it, the whole request uses the long-context tier**, including all input, cache reads, cache writes, and output. Only charging the excess at the higher rate would be incorrect. Current official baselines: [Luna](https://developers.openai.com/api/docs/models/gpt-5.6-luna), [Terra](https://developers.openai.com/api/docs/models/gpt-5.6-terra), and [Sol](https://developers.openai.com/api/docs/models/gpt-5.6-sol).

### Cache and reasoning tokens

Within total input, cache reads and writes each replace the uncached-input charge. Cache writes cost 1.25 times the selected tier's uncached-input rate; **do not charge uncached input first and then add another 1.25 times the rate**. See the official [prompt caching guide](https://developers.openai.com/api/docs/guides/prompt-caching).

```text
P = total input, including cache reads and writes
R = actual cache-read tokens
W = actual cache-write tokens
O = total output, already including reasoning

Uncached input tokens = P - R - W
Cost (USD) = ((P - R - W) × selected input rate
            + R × selected cache-read rate
            + W × selected cache-write rate
            + O × selected output rate) / 1,000,000
```

`completion_tokens` already includes `completion_tokens_details.reasoning_tokens`; do not add reasoning again. All charge components are summed before conversion to integer quota. The account's applicable billing multiplier and integer units also affect the final debit.

Cache prices apply to usage actually reported by the channel. Luna automatic cache writes, cache reads, and one request above 272K input tokens have passed live billing checks. Terra / Sol cache usage and explicit cache controls or retention durations on all models remain unverified. A listed price does not establish feature availability. If usage contains write components with different retention durations, each needs its corresponding configured price; unknown durations or missing prices must not be treated as zero-cost usage.

### `usage.cost` and final billing

The `usage.cost` value in a non-streaming Chat response or final streaming usage event is the calculated charge in **integer quota units**, not USD or a dollar token rate. Its presence does not prove account settlement has completed. Reconcile the final amount against the call's billing record.

| Text billing state | Meaning |
|---|---|
| `reserved` | Quota reserved; outcome not yet confirmed. The reservation is not the final charge |
| `pricing_pending` | Usage received, but pricing or measurement needs review. The reservation remains; no confirmed charge is published |
| `settlement_pending` / `refund_pending` | Settlement or refund is still pending |
| `settled` / `refunded` | Debit or refund completed. Use the final billing amount for reconciliation |

These are text billing-record states, not a new `billing_status` field in Chat responses or asynchronous media tasks. Missing usage, a missing cost, or a dropped connection does not mean the call was free. Check the existing call and billing state before submitting again. When a cache-write price cannot be verified, the gateway does not pass a supplier's USD `cost` through as quota.

## Chat integration

Set `WAVE_API_KEY` to your own WaveAPI key. The examples use Luna; replace `model` with either other public ID as needed, subject to the validation scope below.

<CodeGroup>

```bash Non-streaming
curl https://www.qingbo.dev/v1/chat/completions \
  -H "Authorization: Bearer $WAVE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-5.6-luna",
    "messages": [{"role": "user", "content": "Reply with one short greeting."}],
    "max_completion_tokens": 128,
    "reasoning_effort": "none",
    "stream": false
  }'
```

```bash Streaming
curl -N https://www.qingbo.dev/v1/chat/completions \
  -H "Authorization: Bearer $WAVE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-5.6-luna",
    "messages": [{"role": "user", "content": "Reply with one short greeting."}],
    "max_completion_tokens": 128,
    "reasoning_effort": "none",
    "stream": true,
    "stream_options": {"include_usage": true}
  }'
```

</CodeGroup>

The `128` token budget was used for this round's short-text checks; it is not a model maximum. The examples retain the verified `reasoning_effort: "none"`. Default reasoning behavior and other effort levels remain unverified. When enabled, reasoning also consumes output tokens. A `finish_reason` of `length` can indicate an unfinished answer and does not establish complete content validation.

### Reading the final SSE usage event safely

A usage event can have an empty `choices` array. Read usage before checking text deltas to avoid losing billing information to an array-index error after generation finishes.

```python
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["WAVE_API_KEY"],
    base_url="https://www.qingbo.dev/v1",
)
stream = client.chat.completions.create(
    model="gpt-5.6-luna",
    messages=[{"role": "user", "content": "Reply with one short greeting."}],
    max_completion_tokens=128,
    reasoning_effort="none",
    stream=True,
    stream_options={"include_usage": True},
)

for chunk in stream:
    if chunk.usage is not None:
        quota_cost = getattr(chunk.usage, "cost", None)
        if quota_cost is not None:
            print(f"\nCalculated charge: {quota_cost} quota")
    if chunk.choices:
        content = chunk.choices[0].delta.content
        if content:
            print(content, end="", flush=True)
```
