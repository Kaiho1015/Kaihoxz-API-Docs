DeepSeek V3.2 Exp, the September 2025 experimental checkpoint, offered as a pinned version for question answering, content organization and tool use. Supports streaming answers and function-call argument generation.

Use `deepseek-v3.2-exp` with `POST /v1/chat/completions`. The scope below follows this model's acceptance records.

Official release date: [2025-09-29](https://api-docs.deepseek.com/news/news250929). This ID names that exact checkpoint and does not move with an alias.

**Relationship to `deepseek-v3.2`**: these are two separately dated DeepSeek releases. This page is the experimental checkpoint of 2025-09-29; [`deepseek-v3.2`](/en/api-reference/text/deepseek-v3-2) is the general release of 2025-12-01. They are two independent models in this catalogue, so pick the one you mean.

## Pricing and billing

These are WaveAPI sale prices in **USD per 1 million tokens**.

| Billing dimension | WaveAPI rate |
|---|---:|
| Total input tokens | 0.252 |
| Output tokens | 0.378 |

### About the official price reference

The official reference does not establish support for every official billing feature on this route. **The official price for this model is historical; it is not a price DeepSeek's API offers today**: while this version was served on the author's main API, the official [pricing page](https://api-docs.deepseek.com/quick_start/pricing) listed input 0.28 and output 0.42, with a 0.028 cache-hit rate. That page now lists other models and no longer includes this version.

Total input includes any reported cache statistics and is billed at the ordinary input rate. Cache statistics are part of input, not an extra amount to add again. This integration offers only input and output billing, with no separate cache discount, cache creation, or storage capability.

Explicit `cache_control` requests are rejected before quota reservation.

`completion_tokens` already includes reasoning tokens in its detail fields; do not add them again. Missing usage does not mean zero cost.

```text
USD = (total_input_tokens * applicable_input_rate
     + completion_tokens * applicable_output_rate) / 1,000,000
```

The formula requires complete usage. The gateway converts it to base quota; with the per-request minimum enabled, a request with positive usage and less than 1 base quota is raised to 1 before applying the account group multiplier and taking the integer part. The verified standard group uses multiplier 1, so its minimum charge for positive usage is 1 quota per request. The USD value of 1 quota depends on gateway conversion settings. A very small request can therefore cost more than the unrounded formula amount.

Response `usage.cost` is an integer quota amount, not USD. Reconcile it with console usage records.

## Supported features

This integration supports the following text features:

- Chat function-call argument generation
- Non-streaming Chat text and usage
- Streaming Chat text and final usage

Tool calls return function names and arguments for your application to execute.

Strict Chat JSON Schema output is not offered on this integration: a strict schema request returns ordinary JSON text with no guarantee that the schema is satisfied. If you need strict schema enforcement, choose a model that declares structured output, such as [`deepseek-v3.2`](/en/api-reference/text/deepseek-v3-2).

## Request example

Set `WAVE_API_KEY` to your own key. This example explicitly selects non-streaming and a requested 256-token budget, without adding a reasoning parameter.

```bash
curl http://localhost:40081/v1/chat/completions \
  -H "Authorization: Bearer $WAVE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
  "model": "deepseek-v3.2-exp",
  "messages": [
    {
      "role": "user",
      "content": "Reply with one short greeting."
    }
  ],
  "stream": false,
  "max_tokens": 256
}'
```

Replace the gateway URL for your deployment. `max_tokens=256` is an example request parameter, not a model limit or total-cost guarantee. If the connection drops or final usage is absent, inspect existing usage records before retrying.
