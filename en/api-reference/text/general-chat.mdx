---
title: "General Chat API"
api: "POST https://www.qingbo.dev/v1/chat/completions"
---

- Unified chat API supporting all major text generation models
- Fully compatible with the OpenAI Chat Completions API format
- Switch between AI models seamlessly via the `model` parameter
- Supports streaming, function calling, and other advanced features

<RequestExample>
```bash cURL
curl -X POST https://www.qingbo.dev/v1/chat/completions \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-5.6-luna",
    "messages": [
      {
        "role": "system",
        "content": "你是一个专业的AI助手。"
      },
      {
        "role": "user",
        "content": "解释一下冒泡排序算法。"
      }
    ],
    "temperature": 0.7,
    "max_tokens": 1024
  }'
```

```python Python
from openai import OpenAI

client = OpenAI(
    base_url="https://www.qingbo.dev/v1",
    api_key="YOUR_API_KEY"
)

response = client.chat.completions.create(
    model="gpt-5.6-luna",
    messages=[
        {"role": "system", "content": "你是一个专业的AI助手。"},
        {"role": "user", "content": "解释一下冒泡排序算法。"}
    ],
    temperature=0.7,
    max_tokens=1024
)

print(response.choices[0].message.content)
```

```go Go
package main

import (
    "bytes"
    "encoding/json"
    "fmt"
    "io"
    "net/http"
)

func main() {
    payload := map[string]interface{}{
        "model": "gpt-5.6-luna",
        "messages": []map[string]string{
            {"role": "system", "content": "你是一个专业的AI助手。"},
            {"role": "user", "content": "解释一下冒泡排序算法。"},
        },
        "temperature": 0.7,
        "max_tokens": 1024,
    }

    body, _ := json.Marshal(payload)
    req, _ := http.NewRequest("POST", "https://www.qingbo.dev/v1/chat/completions", bytes.NewBuffer(body))
    req.Header.Set("Authorization", "Bearer YOUR_API_KEY")
    req.Header.Set("Content-Type", "application/json")

    resp, err := http.DefaultClient.Do(req)
    if err != nil {
        panic(err)
    }
    defer resp.Body.Close()

    result, _ := io.ReadAll(resp.Body)
    fmt.Println(string(result))
}
```

## Authorizations

<ParamField header="Authorization" type="string" required>
  All endpoints require Bearer Token authentication.

  Get your API Key:

  Visit the [API Key management page](https://qingbo.dev/dashboard/keys) to obtain your API Key.

## Body

<ParamField body="model" type="string" required>
  Model ID.

  For the full list of models with prices and verified capabilities, see the [Text Models Overview](/en/api-reference/text/overview); live availability comes from `GET /v1/models`.

  Switching models means changing this field only. Which parameters work depends on that model's verified capabilities — not every OpenAI option is available everywhere: GPT-5 and later use `max_completion_tokens` and `reasoning_effort`, Claude uses `max_tokens`, and `gpt-5-pro`, `gpt-5.2-pro`, `gpt-5.4-pro`, `gpt-5.3-codex` and `o3-pro` accept only the [Responses API](/en/api-reference/text/openai-multimodal).
</ParamField>

<ParamField body="messages" type="array" required>
  List of conversation messages.

  <Expandable title="Message object properties">
    <ParamField body="role" type="string" required>
      Role: `system` (system prompt), `user` (user input), or `assistant` (model reply).
    </ParamField>

    <ParamField body="content" type="string" required>
      Message content. Accepts a string or an array of multimodal content parts.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="temperature" type="number">
  Controls output randomness, range 0–2.

  * Lower values (e.g., 0.2) make output more deterministic.
  * Higher values (e.g., 1.8) make output more random.

  Default: 1.0
</ParamField>

<ParamField body="max_tokens" type="integer">
  Maximum number of tokens to generate.

  The maximum allowed value varies by model — refer to the specific model documentation.
</ParamField>

<ParamField body="stream" type="boolean">
  Whether to use streaming output.

  * `true`: Stream the response as Server-Sent Events (SSE).
  * `false`: Return the full response in one go.

  Default: false
</ParamField>

<ParamField body="top_p" type="number">
  Nucleus sampling parameter, range 0–1.

  Controls diversity. We recommend using either `temperature` or `top_p`, not both.

  Default: 1.0
</ParamField>

<ParamField body="frequency_penalty" type="number">
  Frequency penalty, range -2.0 to 2.0.

  Positive values reduce the likelihood of repeating the same words.

  Default: 0
</ParamField>

<ParamField body="presence_penalty" type="number">
  Presence penalty, range -2.0 to 2.0.

  Positive values increase the likelihood of introducing new topics.

  Default: 0
</ParamField>

<ParamField body="stop" type="string or array">
  Stop sequences.

  Up to 4 sequences. Generation stops when any of them is encountered.
</ParamField>

<ParamField body="n" type="integer">
  Number of completions to generate.

  Default: 1
</ParamField>

<ParamField body="max_completion_tokens" type="integer">
  Output token budget (OpenAI GPT-5 and later).

  These models reject `max_tokens`; use this field instead. Reasoning tokens come out of the same budget: `finish_reason: "length"` means the answer may be unfinished and must not be accepted as complete.
</ParamField>

<ParamField body="reasoning_effort" type="string">
  Reasoning tier (OpenAI reasoning models).

  One of `none` / `low` / `medium` / `high`. GPT-5.6 and GPT-5.4 / 5.5 were accepted with `none`; GPT-6 Astra was accepted with `low` only and rejects `none`. Do not send this field to non-OpenAI models.
</ParamField>

<ParamField body="stream_options" type="object">
  Streaming options.

  With `{"include_usage": true}` the SSE stream emits one extra usage-only event before `[DONE]`. **That frame's `choices` can be an empty array** — read usage first, then check for a text delta, or an index error will drop the cost information. See [Streaming](/en/docs/streaming).
</ParamField>

<ParamField body="response_format" type="object">
  Structured output.

  `{"type": "json_schema", "json_schema": {...}}` constrains the reply to a JSON Schema; `{"type": "json_object"}` only guarantees valid JSON. Available only on models whose Verified column includes JSON; **the whole Claude line currently rejects it** (400 before reservation), and DeepSeek V3.2-Exp / V3.1-Terminus offer no strict schema.
</ParamField>

<ParamField body="tools" type="array">
  Function declarations available to the model.

  `[{"type": "function", "function": {"name": ..., "description": ..., "parameters": {JSON Schema}}}]`. The model only generates a function name and arguments in the response's `tool_calls`; **the gateway executes nothing** — running the tool and feeding the result back is your application's job. Available only on models whose Verified column includes tools.
</ParamField>

<ParamField body="tool_choice" type="string or object">
  How tools are selected.

  `"auto"` (default), `"none"`, or `{"type": "function", "function": {"name": "..."}}` to force a specific function. **The Claude Fable family accepts only `"auto"`**; `required` or a named function is rejected upstream (400, reservation fully refunded).
</ParamField>

## Available models

Model IDs, prices, long-context tiers and per-model verified capabilities all live in the [Text Models Overview](/en/api-reference/text/overview); this page does not keep a second copy that would drift. Live availability and price configuration come from the catalog API:

```bash
curl https://www.qingbo.dev/v1/models \
  -H "Authorization: Bearer YOUR_API_KEY"
```

## Usage and billing

`usage.prompt_tokens` is total input and already includes `prompt_tokens_details.cached_tokens`; `usage.completion_tokens` already includes `completion_tokens_details.reasoning_tokens`. Cached tokens are billed at the cache rate instead of the ordinary input rate, and reasoning is billed once at the output rate — neither is added twice.

`usage.cost` in the response is an integer **quota**, not dollars (500,000 quota = 1 USD). The final charge is the text ledger entry in your billing records; `pricing_pending` means reconciliation is outstanding, not a zero charge. Full rules, ledger states and the cost formula are in the [Text Models Overview · Billing rules](/en/api-reference/text/overview#billing-rules).

<Warning>
A missing final `usage`, a dropped connection or a response without a cost field does not make the call free. Check the existing usage record in the console before resubmitting.
</Warning>
