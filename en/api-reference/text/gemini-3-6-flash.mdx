Use the public model ID `gemini-3.6-flash` for text generation. The OpenAI-compatible endpoint is `POST /v1/chat/completions`; Gemini native requests use `/v1beta`.

<Note>
This round verified non-streaming and streaming short-text requests in both Chat Completions and Gemini native formats, plus JSON Schema and function-call outputs through Chat, in the integration environment. Further capabilities are tracked individually below; examples do not establish support for every parameter. These checks do not confirm production deployment. Check account availability in the [model catalog](/en/docs/models) before calling.
</Note>

## Pricing and billing

These are standard text request prices in **USD per 1 million tokens**, not Batch or Flex prices.

| Billing dimension | Google official standard price | WaveAPI standard price |
|---|---:|---:|
| Uncached input | $1.50 | **$1.35** |
| Output, including reasoning tokens | $7.50 | **$6.75** |
| Cached input reads | $0.15 | **$0.135** |

The official baseline is the [Google Gemini API pricing page in Simplified Chinese](https://ai.google.dev/gemini-api/docs/pricing?hl=zh-cn). These rates do not cover cache storage, search grounding, or additional tool charges. Their integration and billing are incomplete. Built-in tools, `web_search_options`, Gemini explicit caching, and `service_tier` values other than `standard` / `default` are currently rejected before quota reservation. Ordinary caller-executed function calls are not built-in tools; see their channel validation status below.

### Counting tokens

- `prompt_tokens` is total input. Cache hits reported in `prompt_tokens_details.cached_tokens` use the cached-input rate; the remaining input uses the uncached-input rate.
- `completion_tokens` already includes `completion_tokens_details.reasoning_tokens`. Reasoning is charged at the output rate and **must not be added again**.
- The cached-input rate applies to reported cache-hit usage. It does not establish support for cache creation or storage APIs; cache-hit validation is still pending.

For a standard text request with complete usage, the dollar calculation is:

```text
Uncached input tokens = prompt_tokens - cached_tokens
Cost (USD) = (uncached input tokens × 1.35
            + cached_tokens × 0.135
            + completion_tokens × 6.75) / 1,000,000
```

For example, 1,000 input tokens with 400 cached tokens and 200 output tokens (including reasoning) cost **$0.002214** at these rates. This is an illustrative calculation, not a request receipt; debits also use integer quota units.

### Response cost fields

Chat Completions returns `usage.cost` in **quota units (an integer)**, not USD. Read the response `usage` for non-streaming calls and the final usage event for streaming calls. Do not combine dollar prices directly with that integer. See [request and response format](/en/docs/request-response) and [streaming](/en/docs/streaming).

If usage is missing or a connection drops, do not interpret the missing cost as zero or automatically generate again just because the final event is absent. Check the existing call in your console usage records first.

## OpenAI-compatible integration

These examples send text requests. Set `WAVE_API_KEY` to your own WaveAPI key.

<CodeGroup>

```bash Non-streaming
curl https://www.qingbo.dev/v1/chat/completions \
  -H "Authorization: Bearer $WAVE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gemini-3.6-flash",
    "messages": [{"role": "user", "content": "Reply with one short greeting."}],
    "max_tokens": 128,
    "stream": false
  }'
```

```bash Streaming
curl -N https://www.qingbo.dev/v1/chat/completions \
  -H "Authorization: Bearer $WAVE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gemini-3.6-flash",
    "messages": [{"role": "user", "content": "Reply with one short greeting."}],
    "max_tokens": 128,
    "stream": true,
    "stream_options": {"include_usage": true}
  }'
```

</CodeGroup>

The `128` token budget is a short-text test example. Reasoning also consumes output tokens. A `finish_reason` of `length` can mean the budget ran out before the visible answer finished; this does not establish inability to answer or a complete content validation.

### Reading streamed output with an SDK

This example uses the OpenAI Python SDK. A usage event can contain an empty `choices` array: read usage before checking for text deltas.

```python
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["WAVE_API_KEY"],
    base_url="https://www.qingbo.dev/v1",
)

stream = client.chat.completions.create(
    model="gemini-3.6-flash",
    messages=[{"role": "user", "content": "Reply with one short greeting."}],
    max_tokens=128,
    stream=True,
    stream_options={"include_usage": True},
)

for chunk in stream:
    if chunk.usage is not None:
        quota_cost = getattr(chunk.usage, "cost", None)
        if quota_cost is not None:
            print(f"\nCharged quota: {quota_cost}")
    if chunk.choices:
        content = chunk.choices[0].delta.content
        if content:
            print(content, end="", flush=True)
```

## Gemini native format

Native requests use `POST /v1beta/models/gemini-3.6-flash:generateContent` with `contents` and `generationConfig`, rather than Chat Completions `messages`. Native non-streaming and streaming short-text requests passed validation in this round; native function calling and structured outputs remain unverified.

```bash
curl https://www.qingbo.dev/v1beta/models/gemini-3.6-flash:generateContent \
  -H "x-goog-api-key: $WAVE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [{"role": "user", "parts": [{"text": "Reply with one short greeting."}]}],
    "generationConfig": {"maxOutputTokens": 128}
  }'
```

Gemini native responses use `usageMetadata` and do not add the gateway `usage.cost` field. Check native request charges in your console usage records.

A native stream can end with a usage-only event containing `candidates: []`. Read `usageMetadata` even when no candidate text is present. The observed final event reported 8 input, 1 candidate-output, and 77 thinking tokens, totaling 86. Native `candidatesTokenCount` and `thoughtsTokenCount` are reported separately; do not interpret either as Chat `completion_tokens`, which already includes reasoning.

## Official capabilities and integration validation

The [Google model page](https://ai.google.dev/gemini-api/docs/models/gemini-3.6-flash) lists an input limit of **1,048,576 tokens**, an output limit of **65,536 tokens**, and support for thinking, function calling, and structured outputs. These are official model specifications; they do not establish equivalent tested limits or parameter support on this channel.

| Item | Current channel validation |
|---|---|
| Non-streaming Chat Completions with short text | HTTP 200, with text and usage |
| Streaming Chat Completions with short text and final usage | HTTP 200, with usage and `[DONE]` |
| Gemini native non-streaming text requests | HTTP 200, with text and `usageMetadata` |
| Gemini native streaming requests | HTTP 200, with text and a preserved usage-only event containing `candidates: []` |
| JSON Schema through Chat | HTTP 200, returning `{"answer":"OK"}` matching the sample schema |
| Forced function call through Chat | HTTP 200, returning `record_result` with `{"answer":"OK"}`; the function was not executed |
| Gemini native function calling and structured outputs | Officially supported; unverified on this channel |
| Long context and maximum output | Official limits checked; channel limits unverified |
| Multimodal input and cache hits | Not verified in this round |
| Cache storage, grounding, and extra tool charges | Integration and billing incomplete; not offered by this page |

The two short-text Chat Completions checks returned 275 and 184 quota, totaling 459 quota. Account debits, key usage, and consumption records matched. The separate JSON Schema and function-call checks returned 404 and 614 quota. These are results for specific test requests, not a fixed per-request fee.

Priority, `web_search`, and Gemini `cache_control` requests for unsupported additional-charge features each returned HTTP 400 with no new billing records. Function-call validation covers argument generation only; caller-side execution and subsequent conversation turns still need application-specific validation.

See [General Chat API](/en/api-reference/text/general-chat) for the common request structure and errors, and [authentication](/en/docs/authentication) for key usage.
